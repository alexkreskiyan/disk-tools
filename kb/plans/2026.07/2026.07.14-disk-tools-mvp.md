# Execution Plan: disk-tools MVP (scan + large files)

## Overview

Deliver `disk-tools` v0.1: a cross-platform CLI that scans a path in parallel and prints a **dust-style size-sorted tree** of the largest directories and files by real on-disk size, limited by `-n` and `--depth`. Built as a Cargo workspace with `disk-tools-core` (lib) + `disk-tools` (bin). Cleanup, junk/old/duplicate detectors, TOML config, and TUI are explicitly out of scope here (see concept for the full vision).

## Phases

### Phase 1: Workspace scaffold

**Goal:** Compiling Cargo workspace with core-lib + CLI split.

**Tasks:**
- [ ] `cargo init` workspace: root `Cargo.toml` with members `core/` (`disk-tools-core`) and `cli/` (`disk-tools`, `[[bin]] name = "disk-tools"`).
- [ ] Add MVP deps: core → `rayon`, `filesize` (walker decided: `std::fs::read_dir` + `rayon::scope` — **not** `walkdir`, not `ignore`). CLI → `clap` (derive), `indicatif`, `terminal_size`, `disk-tools-core`. Dev: `tempfile`.
- [ ] Pin MSRV (≥ 1.85 to satisfy `rayon`; verify against final lockfile), edition 2021, `#![forbid(unsafe_code)]` in core (add a scoped `#[allow(unsafe_code)]` only if a future `statx`/platform size-shim needs it — `filesize` keeps its unsafe internal, so forbid holds for MVP).
- [ ] Update root `.gitignore` already covers `/target/` — confirm.

### Phase 2: Walker implementation & validation

**Goal:** Fast `read_dir`+`rayon::scope` walk in a plain `core::walk` module, validated on real trees.

**Tasks:**
- [ ] Implement `core::walk` (`std::fs::read_dir` + `rayon::scope` recursion) as a plain module/function — no walker trait abstraction. Own `st_dev` check for `--one-file-system`; symlinks not followed, so no loop detection needed.
- [ ] Confirm `DirEntry::file_type()` drives dir/file/symlink decisions — no speculative `metadata()` (one metadata/size call per real file only).
- [ ] Bench on concrete datasets: a `node_modules`-heavy project tree, `~/Library/Caches` (macOS), and a flat media library. Compare wall-clock vs `du -sh`/`diskus`; record numbers.

### Phase 3: Sizing + dedup core

**Goal:** Correct per-file size and hardlink accounting.

**Tasks:**
- [ ] `filesize`-based allocated size per file; also capture apparent `len()`.
- [ ] Dedup key: `(dev, inode)` (Unix) / `(volume_serial, file_index)` (Windows) — count each once.
- [ ] Cross-directory hardlink rule: attribute an inode's size to the **lexicographically first** of its paths, resolved in a post-collection pass, so directory totals sum to the root total **and are identical across runs**. ("First occurrence in the walk" is nondeterministic under parallelism.) Document explicitly.
- [ ] Graceful skip on `PermissionDenied` and `NotFound` (TOCTOU); collect skipped entries (path + reason) **as data into `ScanResult`** — core does not log or print (frontend presents them; see Phase 5).
- [ ] No-follow-symlinks default; `--one-file-system` (`same_file_system`) option.
- [ ] Define `ScanNode` / `ScanTree` model + size-unit formatting — a size-annotated tree (`path`, allocated + apparent size, `is_dir`, `children`) plus a skipped list. Drives the dust-style tree report and JSON now; the future TUI reuses the same tree.

### Phase 4: Aggregation + tree rendering

**Goal:** Turn the walk into a size-sorted tree.

**Tasks:**
- [ ] Bottom-up subtree size aggregation (rayon reduce) into the `ScanTree`.
- [ ] Size-sorted rendering: children ordered by size. `-n`, `--depth` and `--min-size` are **display-time filters only** — `--depth` limits shown depth while totals still reflect the full subtree (`du --max-depth` semantics), `--min-size` hides entries without changing parent totals. Proportional bars per entry (dust-style), sized via `terminal_size` with a fixed fallback when piped.
- [ ] Unit tests on a fixture tree (known sizes, a hardlink pair, an unreadable dir, a symlink). Gate the symlink fixture with `#[cfg(unix)]` — **skip on Windows for now** (symlink creation needs admin/Developer Mode; keep CI green). Hardlink + unreadable-dir cases run on all platforms.

### Phase 5: CLI frontend

**Goal:** Usable `disk-tools` binary.

**Tasks:**
- [ ] `clap` derive: `disk-tools <PATH> [-n 20] [--min-size 0] [--depth N] [--apparent] [--one-file-system] [--json] [--verbose]`. `<PATH>` **required** (no implicit CWD scan); `--depth` default unlimited (display depth).
- [ ] Human report: dust-style size-sorted tree with proportional bars, largest first.
- [ ] `--json` machine output (for scripting/future frontends).
- [ ] `indicatif` spinner during scan. **Stream discipline:** JSON → stdout; spinner and skipped summary → stderr, so `--json` stays parseable when piped.
- [ ] Print skipped-paths summary at end as a **count + first 10 paths** (not the full list — a system scan can hit thousands of permission-denied entries); `--verbose` to dump all.
- [ ] Reserve `ArgGroup` for future report-vs-interactive exclusivity.

### Phase 6: Cross-platform CI + docs

**Goal:** Green on all three targets, documented.

**Tasks:**
- [ ] GitHub Actions matrix: macOS + Linux + Windows; `cargo build`, `cargo test`, `clippy -D warnings`, `fmt --check`. Symlink tests are `#[cfg(unix)]`-gated, so the Windows job stays green without privilege setup (revisit Developer-Mode symlink coverage later).
- [ ] README with usage + examples; note APFS-clone overcount limitation.
- [ ] Re-run `/document-repository` to refresh CLAUDE.md + kb snapshots against real code.

## Verification

- `disk-tools ~/some/dir` prints a size-sorted tree of the largest entries; root total matches `du -sh` within block-rounding on Linux/macOS.
- `<PATH>` is required — running `disk-tools` with no path errors out, never scans CWD implicitly.
- Hardlinked file counted once; unreadable dir collected into `ScanResult.skipped` and surfaced by the CLI, not a crash.
- `--json` output parses and matches the human report.
- CI matrix green on macOS/Linux/Windows; no clippy warnings.
- Symlinks not followed by default; `--one-file-system` stops at mount boundaries.

## Risks

| Risk | Mitigation |
|------|------------|
| Walker too slow on real workloads | Phase 2 validates `read_dir`+`rayon::scope` perf on deep + flat trees vs `du`/`diskus`; tune before locking. Flat dirs parallelize worse (unit of work is a directory) — batch files via `par_iter` within a dir if profiling shows it. |
| Windows allocated-size / long-path edge cases | Use `filesize` crate; avoid `canonicalize()`; test on real NTFS-compressed + sparse file; CI on Windows from day one. |
| APFS COW clones overcount size | Documented limitation; no cheap fix — surface in README/report notes. |
| Memory on whole-volume (`/`) scans | Full tree retained for dir top-N; watch memory on millions of files. Files-only streaming (bounded heap) is the fallback if it bites. |
| Scope creep into cleanup/TUI | Hard MVP boundary: scan + large-files report only; everything else deferred to concept follow-ups. |
| `jwalk` temptation (stale) | Explicitly excluded; use `read_dir`+`rayon::scope`. |
