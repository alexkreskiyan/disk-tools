# disk-tools — large-file / junk finder

## Original Question

Build a console disk-utilities tool in Rust (binary name `disk-tools`) in this repo. First feature: find large files / junk on disk to then clean it up. Needs to be **fast** and **ergonomic**, with **optional configuration** (what to scan, what to auto-clean, what to clean manually).

## Discussion Insights

Decisions made during the session:

| Dimension | Decision |
|-----------|----------|
| Platform | Cross-platform incl. **Windows** (macOS/Linux/Windows) |
| Detectors (full vision) | Large files, junk patterns, old/forgotten files, duplicates |
| **MVP scope** | **Scan + large files only** — rest deferred |
| UX model | **Hybrid** — fast CLI report by default, optional interactive (`--interactive`) for cleanup |
| Auto-clean safety | Auto only for explicit **safe-list** from config; everything else manual; **move to trash, not rm** |
| Config | **TOML, optional** — sane defaults, config sets paths/excludes/safe-list |
| Architecture | **core-lib + CLI from the start** (czkawka model) — TUI/dedup become later frontends/modules |

## Research Summary

Full report: [2026.07.14-technical-rust-disk-cleanup.md](../../research/2026.07/2026.07.14-technical-rust-disk-cleanup.md)

- **Speed** is dominated by per-entry syscalls, not directory enumeration. Use `DirEntry::file_type()` (free) instead of `metadata()` for type checks; do the one metadata/size call only on real files. Parallelize the walk (`ignore::WalkParallel` or `walkdir`+`rayon`, à la diskus). **Avoid `jwalk`** — unmaintained since Dec 2022.
- **Size correctness**: rank by *allocated* size (`filesize` crate: Unix `blocks()*512`, Windows `GetCompressedFileSizeW`), not apparent `len()`. Dedup by `(dev,inode)` / `(volume,file_index)` to avoid double-counting hardlinks. APFS COW clones can't be cheaply detected → document as a known overcount limitation.
- **Reference tools**: diskus (fast core), dua-cli (report+TUI hybrid — closest match), czkawka (core-lib + multiple frontends — architecture model), fclones/rmlint (staged dedup for later).
- **Safe cleanup** (later): safe-list + marker-aware detection (`target/` only next to `Cargo.toml`), git-dirty guard, `trash` crate. Never touch system caches / Application Support.
- **Crate stack**: `ignore`/`walkdir`+`rayon`, `filesize`, `clap` v4 derive, `indicatif`, `serde`+`toml`, `directories`; later `blake3`+`xxh3-128`, `ratatui`+`crossterm`, `trash`.

## Synthesis

The "fast + ergonomic + optional config" goal maps cleanly onto a proven design: copy diskus's parallel size-aggregation core, wrap it in a `disk-tools-core` library, and expose a `clap` CLI that prints a top-N large-files/dirs report. Correctness (allocated size + inode dedup) must be in the MVP or the rankings mislead. The hybrid UX and safe cleanup are additive layers over the same core, so the core-lib decision pays off immediately for structure and later for TUI/dedup.

## Final Formulation

**disk-tools v0.1 (MVP):** a cross-platform Rust CLI that recursively scans a path in parallel and reports the top-N largest files and directories by real on-disk size, with graceful permission/vanish handling, no-follow-symlinks by default, same-filesystem option, and human/JSON output. Architected as `disk-tools-core` (lib) + `disk-tools` (CLI bin). Cleanup, junk-patterns, old-file and duplicate detectors, TOML config, and interactive TUI are planned follow-ups over the same core.
