# disk-tools — Rust Crate Structure

## Workspace

`Cargo.toml` at the root:

```toml
[workspace]
members = ["core", "cli"]
resolver = "3"

[workspace.package]
version = "0.1.0"
edition = "2024"
rust-version = "1.85"
```

Edition 2024 stabilised in exactly 1.85, so the MSRV that `rayon` already forces
makes the newer edition free. Both member crates inherit `version`, `edition` and
`rust-version` from the workspace — there is no `rust-toolchain.toml`; the MSRV is
enforced by the manifest plus a CI job pinned to 1.85.

## The two crates

| Crate | Package | Kind | Role |
|-------|---------|------|------|
| `core/` | `disk-tools-core` | lib | The scanning engine. Silent: no printing, no logging |
| `cli/` | `disk-tools` | bin (`disk-tools`) | Argument parsing, rendering, process exit codes |

The arrow points one way — `cli → core` — so the engine can be depended on,
tested and (eventually) published without dragging in clap or a terminal.

### `disk-tools-core`

```
core/src/
├── lib.rs      deny(unsafe_code); pub fn scan(); re-exports
├── options.rs  ScanOptions
├── walk.rs     read_dir + rayon par_iter recursion, skip collection
├── size.rs     allocated + apparent, per platform
├── dedup.rs    hardlink identity → lexicographically-first attribution
└── tree.rs     ScanNode / ScanTree / SkippedEntry / SkipReason + aggregation
```

Every module except `lib.rs` is private; the public surface is exactly
`scan`, `ScanOptions`, `ScanNode`, `ScanTree`, `SkipReason`, `SkippedEntry`
(`core/src/lib.rs:24-25`).

Dependencies:

| Dependency | Why |
|------------|-----|
| `rayon = "1.12"` | Directory-level parallelism in the walk |
| `serde = { version = "1", optional = true }` | Behind the `serde` feature — see below |
| `windows-sys = "0.61"` (Windows only) | `GetCompressedFileSizeW`; Unix builds never see it |
| `tempfile = "3"` (dev) | Filesystem fixtures |

The spec's original sketch also listed a `units.rs` and a `filesize` crate.
Neither exists: size formatting lives in the renderer (only the CLI needs it), and
`filesize` was rejected in Task 2 because its Windows path calls
`std::fs::canonicalize` on every file.

### `disk-tools`

```
cli/src/
├── main.rs     args → scan → render → write; spinner and skips to stderr
├── args.rs     clap derive, parse_size, validate_root
└── render/
    ├── mod.rs
    ├── tree.rs     dust-style tree, parent-relative bars, unicode-aware fitting
    ├── json.rs     --json (full tree, raw byte counts)
    └── skipped.rs  skipped-entries summary, capped at ten
cli/tests/cli.rs    black-box tests against the built binary
```

| Dependency | Why |
|------------|-----|
| `disk-tools-core` (path, `features = ["serde"]`) | The engine |
| `clap = "4.5"` (derive) | Argument surface and `--help` |
| `terminal_size = "0.4"` | Bar layout; falls back to 80 columns when piped |
| `serde_json = "1"` | `--json` |
| `indicatif = "0.17"` | The scan spinner; tty-gates itself |
| `unicode-width = "0.2"` | Terminal column widths for CJK, emoji, combining marks |
| `tempfile = "3"` (dev) | Fixtures for the integration tests |

## The `serde` feature

`core/Cargo.toml`:

```toml
[dependencies]
serde = { version = "1", features = ["derive"], optional = true }

[features]
serde = ["dep:serde"]
```

Every model type carries
`#[cfg_attr(feature = "serde", derive(serde::Serialize, serde::Deserialize))]`
(`core/src/tree.rs`). A library consumer that does not need serialisation pays
nothing; the CLI turns the feature on explicitly (`cli/Cargo.toml:12`) because
`--json` requires it.

The `dep:serde` syntax matters — it declares the optional dependency without also
creating an implicit feature of the same name that could be enabled by accident.

## The unsafe policy

`core/src/lib.rs:16` declares `#![deny(unsafe_code)]` — crate-wide, **`deny` and
not `forbid`**, and that distinction is the whole point: `forbid` cannot be lifted
by a local `#[allow]`, and Windows offers no safe route to a file's allocated size.

The single exemption is `#[allow(unsafe_code)]` on the Windows `allocated`
(`core/src/size.rs:117`), whose one `unsafe` block calls `GetCompressedFileSizeW`
behind a `// SAFETY:` note covering the NUL-terminated buffer and the live output
pointer. That is the only `unsafe` in the workspace; the `cli` crate has none and
needs no attribute.

Any further `allow` should get the same scrutiny this one did.

## Platform-conditional compilation

Three patterns recur:

1. **Alternate function bodies** — `#[cfg(unix)]` / `#[cfg(windows)]` /
   `#[cfg(not(any(unix, windows)))]` implementations of `size::allocated`; a
   `#[cfg(unix)]` / `#[cfg(not(unix))]` pair for `walk::device_of` and
   `walk::file_id`, where the non-Unix arm returns `None` and turns a feature into
   a documented no-op.
2. **Platform-only helpers** — `size::verbatim_if_long` exists only on Windows.
3. **Platform-only dependencies** —
   `[target.'cfg(windows)'.dependencies] windows-sys`.

Cross-checking a Windows build from a Unix machine, without running it:

```bash
cargo clippy --workspace --target x86_64-pc-windows-msvc --all-targets -- -D warnings
```

This catches type errors in `#[cfg(windows)]` code that the local build never
compiles. It is not a substitute for CI, which actually *runs* the tests there —
the NTFS sizing behaviour documented in the overview was found by CI, not by this
check.
