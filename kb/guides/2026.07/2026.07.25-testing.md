# disk-tools — Testing Guide

## Running

```bash
just test                                     # cargo test --workspace
just verify                                   # fmt-check + lint + test — the gate
cargo test -p disk-tools-core -- --ignored    # the one mount-point test
cargo test -p disk-tools --bins               # CLI unit tests only
cargo test -p disk-tools --test cli           # CLI integration tests only
```

`disk-tools` has no library target, so `cargo test -p disk-tools --lib` fails with
`no library targets found` — use `--bins`.

## Layout

Unit tests live **in-module** (`#[cfg(test)] mod tests` at the bottom of each
source file), so they can exercise `pub(crate)` internals like `walk::walk`,
`dedup::attribute` and `size::measure` without widening the public API.

| File | Tests | Covers |
|------|-------|--------|
| `core/src/options.rs` | 1 | Defaults |
| `core/src/size.rs` | 9 | Allocated vs apparent, sparse files, long paths, the Windows contract |
| `core/src/walk.rs` | 10 | Traversal, skips, symlinks, filesystem boundaries |
| `core/src/dedup.rs` | 10 | Hardlink attribution and determinism |
| `core/src/tree.rs` | 9 | Bottom-up aggregation, ordering, `du` cross-check |
| `cli/src/args.rs` | 16 | Argument parsing, size suffixes, overflow, root validation |
| `cli/src/render/tree.rs` | 24 | Layout, bars, filters, unicode width |
| `cli/src/render/json.rs` | 9 | Wire shape and round-tripping |
| `cli/src/render/skipped.rs` | 10 | Preview cap and wording |
| `cli/tests/cli.rs` | 16 | The real binary end to end |
| **Total** | **114** | |

`cli/tests/cli.rs` is the only out-of-module suite. It spawns the actual
executable through `env!("CARGO_BIN_EXE_disk-tools")` rather than calling into the
crate, because what it checks — exit codes, which stream output lands on, JSON
validity when piped, broken-pipe behaviour — only exists at the process boundary.

## Platform gating

| Gate | Where | Why |
|------|-------|-----|
| `#[cfg(unix)]` | permission fixtures, hardlinks, symlinks, sparse files, the `du` cross-check | The semantics either don't exist on Windows or need privileges there |
| `#[cfg(windows)]` | `core/src/size.rs` only | `\\?\` prefixing and the documented `GetCompressedFileSize` contract |
| `#[ignore = "needs a real mount point"]` | `core/src/walk.rs:583` | `one_file_system_stops_at_boundary` needs a genuine second filesystem |

Windows symlink tests are **deliberately absent** rather than ignored: creating a
symlink there needs admin or Developer Mode, and a CI job that requires privilege
setup is a job that breaks. The gated tests compile out entirely, which is why the
Windows job reports 83 tests and `0 ignored` against macOS's 102 — a compile-time
difference, not a runtime skip.

## Fixture patterns

**Temp directories.** Every filesystem test builds its tree under
`tempfile::tempdir()`, with byte sizes chosen so assertions are exact. Where a
test compares formatted output, sizes are powers of 1024 so rounding is
deterministic (`1_048_576` → `"1.0M"`), and `--apparent` is used to sidestep
block-size differences between machines.

**Permission fixtures refuse to pass for the wrong reason.** `chmod 000` does not
stop root, so a test running as root inside a container would sail through while
proving nothing. Every such test checks whether the restriction actually took
effect, and bails loudly if not:

```rust
std::fs::set_permissions(&locked, Permissions::from_mode(0o000))?;

// `chmod 000` doesn't stop root (e.g. inside a container); a test that
// passes because the fixture failed to lock is worse than no test.
if std::fs::read_dir(&locked).is_ok() {
    std::fs::set_permissions(&locked, Permissions::from_mode(0o755))?;
    eprintln!("skipping: running with privileges that ignore chmod 000");
    return;
}
```

Permissions are always restored **before** any assertion can panic, so the
`TempDir` can clean itself up.

**Sparse files use `set_len`, not seek-then-write.** On APFS a seek-then-write
allocates the whole range, producing a non-sparse file and a test that fails for a
reason unrelated to the code.

**Closed pipes.** The broken-pipe tests spawn the binary with `Stdio::piped()`,
read one 64-byte chunk, drop the handle, and assert the child exits `0` without
`panicked` in stderr. The fixture must be big enough (3,000 files) that the report
exceeds the OS pipe buffer — otherwise the child writes everything before the
reader goes away and the path under test is never taken.

## Cross-checking against the system

Two tests validate against external ground truth rather than against our own
arithmetic:

- `root_total_matches_du` (`core/src/tree.rs`, `#[cfg(unix)]`) runs the real
  `du -sk` and compares totals.
- `just bench` compares against `du -sh` and `diskus`, though that is measurement
  rather than a test.

## Mutation testing

`cargo-mutants` has been run ad hoc rather than in CI (`mutants.out/` is
gitignored). Task 9 scoped it to `cli/src/render/skipped.rs` and reached 100%
(9/9). Worth knowing: cargo-mutants does not mutate expressions inside
`writeln!`/`format!` arguments, so arithmetic there produces no mutants and needs
tests that assert on it directly.

## Adding a test

1. Prefer in-module unit tests; reach for `cli/tests/cli.rs` only when the
   behaviour lives at the process boundary.
2. Gate anything needing Unix filesystem semantics with `#[cfg(unix)]`, and add
   the defensive privilege check if it relies on permissions.
3. Anything needing a real mount, an external tool or a specific filesystem gets
   `#[ignore = "<reason>"]` — CI must stay green with no setup.
4. Run `just verify`, then type-check the other platform with
   `cargo clippy --target x86_64-pc-windows-msvc --all-targets -- -D warnings`.
5. Remember what CI catches that local runs cannot: two v0.1 defects — the NTFS
   sizing assumption and an off-by-one in the benchmark fixture generator — were
   found by the Windows job and by review, not by a green macOS test run.
