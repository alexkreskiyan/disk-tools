# Rust disk-cleanup CLI ecosystem — Technical Research

Research supporting **disk-tools** (cross-platform Rust CLI; first feature = find large files/junk, later duplicates/old/junk-patterns; hybrid CLI+TUI; safe delete to trash).

## Overview

| Concern | Recommendation |
|---------|----------------|
| Traversal | `ignore::WalkParallel` (maintained, gitignore filtering built-in) or `walkdir`+`rayon::scope` (diskus-style). Avoid `jwalk` — unmaintained since Dec 2022. |
| Real on-disk size | `filesize` crate — wraps `blocks()*512` (Unix) / `GetCompressedFileSizeW` (Windows), falls back to `len()` elsewhere. |
| Dedup hashing | staged: `xxh3-128` (partial) → `blake3` (full). Never 64-bit hashes for file identity. |
| TUI | `ratatui` v0.30 + `crossterm` backend; background scan thread + channel. |
| Safe delete | `trash` v5.2 (Recycle Bin/Trash). Smoke-test on macOS first. |
| Config | `serde` + `toml`; `directories::ProjectDirs` for cross-platform config/cache paths (≥6.0). |
| CLI | `clap` v4 derive. Progress: `indicatif` (spinner for unbounded scan). |

### Staged duplicate-detection algorithm (fclones/rmlint)

Funnel — expensive full-read runs only on survivors:

1. **Enumerate** — parallel walk, record `(path, size)` for regular files.
2. **Group by size** — bucket by exact byte size; drop singletons (no I/O beyond `stat`). Eliminates the vast majority.
3. **Collapse hardlinks** — within a bucket, merge same `(dev, inode)` — same data, different paths.
4. **Prefix hash** — hash small leading chunk (few KB); split groups, drop new singletons.
5. **Suffix hash** — hash trailing chunk (catches shared-header/diverging-tail files, e.g. archives).
6. **Full hash / byte compare** — only survivors; full-file hash (or `-pp` exact compare) confirms duplicate groups.

Stages run sequentially (pruning compounds); each stage parallel across candidates. fclones tunes stages 4–6 by device type and can persist per-inode hashes for fast re-runs.

### Cross-platform correctness (critical for size accuracy)

**Apparent vs allocated size**
- Apparent = `Metadata::len()` / `st_size` (logical bytes). Allocated = `blocks()*512` (real disk). Normal files: allocated ≥ apparent (block rounding). Sparse: apparent ≫ allocated.
- Unix: `std::os::unix::fs::MetadataExt::blocks()*512` (NOT `blksize`). Windows std does **not** expose allocated size → need `GetCompressedFileSizeW` (reflects NTFS compression + sparse holes). Use `filesize` crate to unify.
- Report a normalized unit explicitly (don't inherit `du`'s 1024 vs `st_blocks` 512 confusion).

**Hardlinks / clones — avoid double-counting**
- Dedup key: `(st_dev, st_ino)` on Unix; `(volume_serial_number(), file_index())` on Windows (both on `std` `MetadataExt`). Count each unique inode once per subtree.
- "Space actually reclaimable" differs from "sum of unique inodes" when links exist **outside** the scanned subtree (needs `nlink` vs links-seen). Document the distinction.
- **APFS COW clones**: `clonefile` shares blocks until diverge; two 2GB clones ≈ 2GB real, but naive walk double-counts. No cheap POSIX API to detect shared extents → **document as known limitation**.
- Windows `number_of_links()` unreliable (undercounts, returns 1 on `\\?\` paths); for dedup the `(volume_serial, file_index)` pair is fine. ReFS needs 128-bit `FileIdInfo`.

**Symlinks / boundaries**
- Default: don't follow (walkdir/ignore default). With `follow_links(true)`, walkdir detects loops (via `same_file` dev+inode ancestor check) → yields `Err`, no infinite loop.
- `.same_file_system(true)` stops crossing filesystem boundaries (uses `st_dev`).

**Errors**
- `read_dir`/walkdir yield `Result` per entry. Match `PermissionDenied` → log+skip, don't abort. TOCTOU: files vanish mid-walk → `NotFound`; treat same as permission skip (unavoidable race).
- Windows long paths: avoid `canonicalize()` (returns `\\?\` form, breaks as cwd, rejected by many tools; can fail on RAM/network disks). Walk raw paths from `read_dir`; add `\\?\` prefix defensively only on `MAX_PATH` errors (deep `node_modules`).

### Performance patterns

- **Biggest win: minimize syscalls per entry.** `DirEntry::file_type()` is free (from `getdents` `d_type`); `entry.metadata()` forces an extra `stat`/`statx` on Unix. Use `file_type()` for dir/file/symlink decisions; do the single metadata call only on real files (where you need size anyway). Clippy lint in progress for `metadata().is_dir()` anti-pattern.
- Linux `statx` with field mask (just `STATX_SIZE`) is cheaper — via `rustix`/`libc` (not std). Prototype if stat dominates.
- Windows: `FindFirstFileExW(..., FIND_FIRST_EX_LARGE_FETCH)` middle-ground; `NtQueryDirectoryFileEx` with big buffer ~40% faster (raw `windows-sys` FFI) — only if enumeration profiles as bottleneck.
- Bottleneck is stat calls, not enumeration. Parallelize directory recursion to hide I/O latency (esp. network/HDD).

### Safe vs unsafe to auto-clean

**Safe (regenerable) — default auto-clean candidates:** `node_modules/`, `target/`, `__pycache__`+`*.pyc`, `build/`/`dist/`/`.next/`, `~/Library/Caches` (user), `~/.cache`, `%LOCALAPPDATA%\Temp`.

**Marker-aware heuristic**: flag `target/`/`build/` only when a sibling marker confirms it (`Cargo.toml`, `pom.xml`). Unambiguous names (`node_modules`, `__pycache__`) need no marker. (pattern from `cleard`.)

**Never auto-delete:** `/Library/Caches` (system, no tilde — distinct from user!), `~/Library/Application Support` / `%APPDATA%` (persistent app data), `/System` + Windows system dirs, project dirs with **uncommitted git changes / recent activity** (warn or refuse), virtualenvs `venv/`/`.venv/` (confirm — recreation less deterministic than lockfile installs).

## Synthesis (how this informs disk-tools)

- **MVP (scan + large files)** is well-served by `walkdir`+`rayon` or `ignore::WalkParallel` + `filesize` + `clap` + `indicatif`. Copy diskus's parallel core; add top-N-by-size reporting.
- **Architecture**: adopt czkawka's model early — a `disk-tools-core` lib (scan/detect/size logic) + thin `clap` CLI, so the later TUI (ratatui) and dedup features are frontends/modules over the same core. Cheap to set up now, expensive to retrofit.
- **Correctness upfront**: even for MVP, dedup by `(dev,inode)`/`(volume,file_index)` and use allocated (not apparent) size, or large-file rankings will mislead. Document the APFS-clone overcount limitation.
- **Safety model** for later cleanup: safe-list auto-clean + marker-aware detection + git-dirty guard + trash (not rm).
