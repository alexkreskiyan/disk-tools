  dated 2026-07-25 and described the pre-v0.2 state; a second same-day snapshot
  would have been two files claiming the same day.
- **Every example captured from a real run** against a purpose-built fixture,
  with the temp path rewritten to `~/code`. Nothing in the README is prose about
  what the tool would print.

  `--apply` removes the `confirm` tier too, and that the concept asks for a
  per-target prompt that is a v0.3 question. Documenting a gap is worth more than
  wording that hides it.

### The errors this task was budgeted to find

v0.1's equivalent caught three factual errors in written documentation. The
budget was right; the errors were somewhere else.

**`--help` was printing a note addressed to whoever maintains `args.rs`.** clap
turns doc comments into help text, and a multi-paragraph one becomes `long_help`.
So anyone who typed `disk-tools --help` read:

> `Option` only because a subcommand replaces it; [`Args::resolve`] rejects the
> case where neither is given…

and the subcommand line rendered `**Dry-run by default**` with the asterisks
intact. Maintainer rationale is now in plain `//` comments, and
`help_is_free_of_markup_and_maintainer_notes` asserts that no markup and no
internal name reaches any help page.

**Writing the latency limitation required measuring it**, which had never been
done — and the measurement found `--safe`, the cautious mode, was the *slowest*
of the three, because it planned twice to count what it had hidden.
`CleanPlan.filtered_out` replaced the second pass: 2.083 s → 1.140 s over 50
repositories. It also removed the subtraction whose overflow Task 6's review had
caught.

Both are the same failure in different clothes: a claim written from what the
code was supposed to do rather than from what it does.
