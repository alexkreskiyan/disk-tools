# Handoff: Task 4 — `clean` with no path

[v0.3 — configuration and declarative rules](../../specs/2026.07/2026.07.26-disk-tools-v0.3-config-rules.md)

## Completed

- `Rules::scan_roots()` — the resolved roots of enabled rules, sorted, with any
  root inside another dropped. Replaces the unused `roots()`.
- `CleanPlan::merge` — one plan from several disjoint roots.
- `CleanArgs.path` is `Option<PathBuf>`; `Mode::Clean` carries
  `roots: Vec<PathBuf>` and `roots_from_rules: bool`.
- `run_clean` walks each root, plans each, merges. `emit` takes
  `&[SkippedEntry]` — it only ever used `tree.skipped`.
- Roots chosen by the rules are announced before the walk.

## Decisions Made During Implementation

- **Merge the plans, not the trees.** A synthetic node above several roots would
  need a path and a size it does not have. Every `CleanPlan` field is additive,
  and safely so *because* `scan_roots` drops nested roots — the doc on `merge`
  says that explicitly, since handing it overlapping roots would double both the
  candidates and the total.
- **A missing root is fatal only when the user named it.** A path typed on the
  command line that is not there is a typo, and an empty report would hide it —
  the same reasoning as `--config` on a missing file. A root that came from a
  rule is a description that may have gone stale, and one such is no reason to
  leave the others uncleaned. `scan_or_report` keeps the check; `run_clean` calls
  it only for a named path.
- **The roots are announced when the rules chose them.** The default config roots
  `user-caches` at the home directory, so a bare `disk-tools clean` walks all of
  it. Slow rather than dangerous — the default is still a dry run — but no one
  should have to guess why it is taking a minute. A user who named a path knows
  where they pointed, so that case stays quiet.
- **"No rule names a directory" is not an empty plan.** "Nothing to clean" is a
  claim about the disk; this is a statement about the configuration, and the two
  remedies — pass a path, or give a rule a root — are different things to go and
  do.

**Gotchas discovered:**

- **The integration suite was scanning the developer's home directory.** Once
  `clean` with no path started walking rule roots, the built-in `user-caches`
  rooted at `~` sent it through all of `/Users/alex` — 93 seconds, every
  unreadable directory reported as a skip. `run()` now sets `HOME`,
  `USERPROFILE` and `XDG_CONFIG_HOME` to a temp directory and clears
  `LOCALAPPDATA`/`APPDATA`. Any new test that spawns the binary must go through
  `spawn()`.
- `PathBuf::join("")` appends a separator, so a bare `~` used to resolve to
  `/home/me/`. Harmless to the comparisons, which are component-wise, but the
  resolved root is printed and a stray trailing slash reads as a bug.
- `Mode::Clean` gained two fields. Any `match` on it needs both, and
  `roots_from_rules` is what decides whether a missing root is fatal.
