## Decisions Made During Implementation

- **Two steps, not one.** The answer to "which rule" is not always "a new one";
  a path already claimed usually wants the rule that claims it widened.
- **Validation is `config.rs`'s, function for function** — `parse_size`,
  `parse_duration`, `Rules::new`. A test puts an accepted rule back through the
  config parser and asserts it comes out the same rule. A second implementation
  would drift, and the one that drifts writes a file the CLI then refuses.
- **A rejected form keeps everything.** Clearing on a typo makes the user retype
  the nine fields that were right.
- **`~` in a prefilled root.** A rule rooted at `/Users/alex/Projects` stops
  working the moment the config is used anywhere else.
- **An edit replaces the rule in place.** Position is precedence.
- **A dialog takes every key.** Leaving the browser's bindings live underneath
  would make `q` quit from inside a half-typed rule.

## Deviations from Spec

The form has **ten** fields, not the eight the spec listed:
`requires-clean-repo` was missing from both, and its absence was a bug — `build`
hardcoded `false`, so editing the built-in `rust-target` silently dropped its
git guard.

`requires-sibling` is not a toggle, though it was proposed as one during review:
it has to name the file that must be there.

**Gotchas discovered:**

- clippy's `large_enum_variant` fires on `Dialog`: a `Form` is ten strings and a
  `Chooser` three. Box the form.
- A `pub` accessor used only by tests is `dead_code`. `is_wrong` calling
  `self.problem()` rather than `self.problem` keeps it live and reads better.
- `Path::ends_with("")` is true for every path — twice a trap in this feature.
