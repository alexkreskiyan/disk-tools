## Completed

- `core`: serde behind a `serde` feature (`serde = { version = "1", features = ["derive"], optional = true }`; `[features] serde = ["dep:serde"]`). `ScanNode`/`ScanTree`/`SkippedEntry`/`SkipReason` gain `#[cfg_attr(feature = "serde", derive(serde::Serialize, serde::Deserialize))]`. - `cli/Cargo.toml`: enables the core `serde` feature + `serde_json`. `#[allow(dead_code)]` dropped from `Args.json`.

## Decisions Made During Implementation

- **`render_json` returns `Result`, not a `String`+`expect`.** serde's `Serialize for Path`/`PathBuf` returns `Err` (not a panic) for non-UTF-8 paths; `render_json` propagates it and `main` prints a clean error and exits 1. Confirmed against serde source that this is an `Error::custom`, never a panic.
- **JSON emits the full tree.** `-n`/`--depth`/`--min-size` are *tree-display* filters (they live in the renderer, never in the core walk/aggregate); `--json` doesn't call the renderer, so it always carries the complete data. Consistent, not a surprise — but see the UX note below.
- **`Deserialize` derived too**, so tests round-trip JSON back to an identical `ScanTree` — a stronger check than "is it valid JSON".
- **Pretty JSON** (`to_string_pretty`) — human-inspectable and still valid for `jq`/parsers.
- **Exit codes:** validation failure = 2 (matches clap's usage-error code); JSON encode failure = 1 (`ExitCode::FAILURE`) — distinct categories (usage vs runtime).
