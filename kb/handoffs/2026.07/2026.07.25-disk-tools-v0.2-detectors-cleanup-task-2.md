## Completed

- `ScanNode.modified: Option<SystemTime>` and `ScanNode.links: Option<u32>` —
  the age and per-inode sharing signals.
- `ScanTree.link_groups: Vec<Vec<PathBuf>>` — which paths in this scan share an
  inode, from the groups `dedup::attribute` already built and discarded.
- `windows_dir` now lifts `LastWriteTime` out of the directory listing it was
  already reading, so Windows pays nothing for the timestamp either.
- A `unix_seconds` serde module: `Option<SystemTime>` on the wire as an optional
  count of whole seconds.

**No new syscall anywhere.** That was the point of doing this now rather than
alongside the rules that consume it.

## Decisions Made During Implementation

- **`modified` is not serde's `SystemTime`.** serde's built-in impl emits a
  nested `{secs_since_epoch, nanos_since_epoch}` object *and refuses to serialize
  any pre-1970 instant* — so one file with a bad clock would turn an entire
  `--json` run into an error. The `unix_seconds` module writes a bare i64 of
  whole seconds instead, negative before 1970. Sub-second precision is lost
  deliberately and pinned by `modified_round_trips_to_whole_seconds`; the age
  rule works in days.
- **Directories carry `links: None`,** like `id`. A directory's `st_nlink`
  counts its subdirectories, which is a different quantity — using it would make
  Task 4's `links > group.len()` test fire on every directory in the tree.
  Covered by `directories_report_no_link_count`.
- **`attribute` returns rather than exposes.** It could have stayed `-> ()` with
  a separate grouping pass, but that would rebuild the same `HashMap<FileId, …>`
  a second time. A reviewer noted the verb now does two things; the two callers
  both name the result, and the alternative costs a full extra pass.
- **The keeper is now `paths[0]`** after sorting, instead of a `min_by` over
  indices. Same rule, same comparison, one sort instead of two traversals — and
  the sorted vector is the group that gets returned.
- **`modified` and `links` are carried per node, never folded.** Only
  `allocated`/`apparent` sum upward. A directory judged by its children's
  timestamps would let the age rule call a freshly-written cache old.

## Deviations from Spec

- The spec's §8.1 does not say how `modified` reaches JSON. The `unix_seconds`
  representation is a decision made here — see above for why the default was
  unusable.
- Directories carrying `links: None` is likewise not in the spec, which only
  specifies file behaviour.
- Four tests beyond the spec's list: `a_directory_carries_its_own_mtime`,
  `directories_report_no_link_count`, `link_groups_are_deterministic_across_runs`,
  and three JSON wire-format tests covering `null`, pre-1970 and precision loss.

## For Next Task

Task 3 — **detectors**. Both signals it needs are now on the model.

Things it should know:

1. **`modified` is `Option`, and `None` means unknown.** Never "old", never
   "new". The spec's §8.2.2 step 3 already says the age rule must not match on
   it; `missing_timestamp_yields_none` is the proof the value really can arrive
   that way.
2. **A directory's `modified` is its own.** That is the signal the age rule is
   built on and it is already correct — `modified_is_carried_per_node_not_aggregated`
   guards it.
3. **Timestamps in `--json` are whole seconds.** Anything comparing a scanned
   tree against a deserialized one must expect the truncation.

For Task 4 specifically:

- **`link_groups` is sorted**, groups by their first path and paths within a
  group by raw bytes, so a plan built from it is deterministic without sorting
  again. `link_groups_are_deterministic_across_runs` is the guard.
- **The first path in a group is the keeper** — the one carrying the bytes. The
  rest are zeroed. That is what makes "is a partner outside this candidate?"
  answerable from the group alone.
- **`links == None` is not `1`.** On Windows every entry is `None`, and reading
  that as "one name, unshared" would silently claim a total is exact when it is
  merely unknown. The spec's criterion for this (Task 4, "the gap is in the
  signal, not the content") depends on the distinction.

Smaller, but worth recording:

- **This is a public API change.** `ScanNode` and `ScanTree` gained fields, so
  any struct literal outside the crate breaks. There are no external consumers
  today; the CLI's fixtures were the only cost, and both render modules now
  funnel through helpers so the next addition is one line each.
- **The `filetime` tests execute only on Windows CI.** The conversion is a pure
  function with no OS calls, but it lives inside `#[cfg(windows)] mod
  windows_dir`, so an epoch-offset error would surface in CI rather than locally.
  Moving it out for faster feedback would separate it from the module that owns
  it — the trade-off was taken knowingly.
- **`just verify` has no doc step**, which is why the private-doc-link warning
  survived to review. Worth adding if a second one ever appears.
