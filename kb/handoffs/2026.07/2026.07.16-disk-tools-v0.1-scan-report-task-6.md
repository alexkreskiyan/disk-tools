## Decisions Made During Implementation

- **`-n`/`--number` and `--json` are CLI-only**, not `ScanOptions` fields — they concern display count and output format, which the core knows nothing about. Declared now so `--help` lists all six flags (AC4); `#[allow(dead_code)]` until Task 7 (`-n`) and Task 8 (`--json`) read them.
- **`#[allow(dead_code)]`, not `#[expect(dead_code)]`, on `number`.** A reviewer suggested `expect` (self-cleaning). It works for `json` (never read) but *not* for `number`: the unit test `number_flag_parses_short_and_long` reads the field, so in the test build the dead-code lint doesn't fire and `expect` would be an unfulfilled expectation → a warning under `clippy --all-targets -D warnings`. Kept `allow` on both for uniformity and correctness; noted inline.
- **`into_scan_options(self)`, not `to_scan_options(&self)`.** Consuming `self` moves `root` instead of cloning it (a reviewer flagged the needless clone). Kept it a named extractor rather than `From<Args>`: the mapping is *partial* (drops `number`/`json`), and a named method signals "the scan subset" more honestly than a total `From` conversion.
- **`main` does not call `scan()`.** Task 6 is the argument surface and validation only; there's nothing to render yet (Task 7), and a silent scan would just burn time. `just run <path>` therefore exits 0 with no output until Task 7.
- **Exit code 2** for the validation-failure path, matching clap's own usage-error code — parse errors and root-validation errors agree, verified by integration tests.
