## Decisions Made During Implementation

- **`cargo install`, not Homebrew.** `brew install diskus hyperfine` failed on an
  unwritable `/opt/homebrew/etc` and would have needed `sudo`; both tools are Rust,
  so `cargo install` sidestepped it entirely.
- **Two invocations are reported, not one.** `disk-tools --depth 0` prints a single
  summary line like `du -sh`; the default prints one line per entry. Comparing only
  the default would have been unfair to `disk-tools`; comparing only `--depth 0`
  would have hidden the render cost. Both are in the table.
- **A review finding invalidated the first measurement round and it was redone.**
  The nesting formula was `1 .. ($d % $nesting)`, which cycles 0..N−1 — leaving a
  fifth of `node_modules` packages and a third of `cache` dirs completely flat, not
  the "nested up to N levels" the note claimed. Fixed to `1 + $d % $nesting`,
  fixtures regenerated, **every timing re-measured**. This mattered: on the flatter
  fixture `du -sh` ran in 166.8 ms and beat the full-tree `disk-tools` run (1.20×
  slower, AC2 PARTIAL); on the correct fixture `du` costs 344.6 ms and loses on every
  row. Single-threaded `du` degrades with directory count where the parallel scanners
  absorb it.
- **`min` is reported next to `mean ± σ`.** Two real-time antivirus daemons scan
  every byte written, and 28 GB of fresh fixtures kept the load average above 13 for
  ten-plus minutes. Measurements were retaken in a calmer window; `min` is the
  statistic least contaminated by such spikes, and two independent series agreed on
  every ordering.
- **`bs=1M`, not `bs=1m`** — GNU `dd` rejects the lowercase suffix BSD accepts, and
  the failure would have landed after minutes of fixture generation.
- **`bench-memory` branches `time -l` / `time -v`** by platform; `-l` is BSD-only.
- **No CI benchmark job.** Numbers from shared runners are noise, and this task's own
  experience with background load is the argument.

## Quality Results

  `just verify` green. No production code was touched.
- **Mutation score:** not run — no new production logic.
- **Review iterations:** 2. Round 1 found five real defects (nesting off-by-one,

- **Remaining findings:**
  1. The measurement machine is not quiet — two AV products plus Spotlight, ~85%
     combined AV CPU even in the calmest window. Absolute numbers would be lower on a
     dedicated machine; the ordering is stable across two series. Recorded in the
     note's Caveats.

     `failed printing to stdout: Broken pipe (os error 32)` (`cli/src/main.rs:49,56`);
     no Windows test would catch `allocated()` regressing to `metadata.len()`
     (`core/src/size.rs`); CI installs only `stable`, so MSRV 1.85 is unverified.

  optimization pass — it buys that by keeping nothing, so closing the gap means
  attacking per-entry allocation, not the walk strategy.

  add per-entry state, that number moves — re-measure with `just bench-memory`.
