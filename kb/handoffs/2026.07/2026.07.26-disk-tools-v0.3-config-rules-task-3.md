# Handoff: Task 3 — Precedence

## Feature Spec

[v0.3 — configuration and declarative rules](../../specs/2026.07/2026.07.26-disk-tools-v0.3-config-rules.md)

## Completed

- `ScanArgs.min_size` and `CleanArgs.min_size` lost `default_value = "0"` and
  became `Option<u64>`. Defaults now live in one place: the merge in
  `Args::resolve`.
- Every overridable setting resolves as flag → file → built-in default, and the
  three `[scan]`/`[report]`/`[clean]` sections are wired to behaviour. The
  `#[cfg_attr(not(test), expect(dead_code))]` markers are gone, as the build
  demanded once they were read.
- `DEFAULT_CONFIG` no longer changes what a scan prints.
- Integration tests are isolated from the runner's own config file.

## Files Changed

- `cli/src/args.rs` — `Option` fields, the merge, and six precedence tests
- `cli/src/config.rs` — expectations removed; `DEFAULT_CONFIG` corrected;
  `parse_for_test` seam added
- `cli/tests/cli.rs` — `XDG_CONFIG_HOME` pointed at an empty temp directory

## Decisions Made During Implementation

- **`-n` absent still prints everything.** The spec's AC 3 asked for a built-in
  default of 20; that would change v0.1 behaviour for every user, not only those
  with a config. The user chose to keep today's behaviour, and `n` ships
  commented out in the template.
- **`depth` left the template entirely.** `--depth 0` shows the root alone, and
  the template said `depth = 0  # 0 = unlimited` — the same value with the
  opposite meaning. After a `config init` every report would have collapsed to
  one line. Now absence means unlimited and `0` means what the flag means.
- **Booleans are one-way, knowingly.** clap distinguishes only "passed" from
  "not passed", so a file that sets `apparent = true` cannot be overruled from
  the command line; that would need a `--no-apparent`. No acceptance criterion
  requires it — they are all numeric — and inventing three flags for an unasked
  requirement is surface without a reason. Stated in the template, in the flags'
  doc comments, and pinned by
  `a_boolean_set_in_the_file_cannot_be_unset_by_a_flag`.
  For `[clean] safe` the one-way direction is the right one: a file may only make
  a cleanup more cautious.
- **Defaults moved into doc comments.** clap prints `[default: …]` only for
  values it applies itself, and it no longer applies these. A flag whose default
  is written down nowhere is undocumented.

## Deviations from Spec

- **AC 3: no built-in `-n` default.** Recorded above; the user's decision.
- **`[clean] --min-size` has no file counterpart.** `[report] min-size` is scan
  only (D18) and a rule carries its own, so the clean flag merges against nothing.
  It is `Option<u64>` for symmetry and unwraps to 0.

## Quality Results

- Tests: **334 passing** — 166 core, 137 CLI unit, 31 integration (was 314)
- `just verify`, Windows clippy, `cargo +1.85 check`, `just check-minimal`: clean
- **By hand:** a config of `min-size = "1M"` gives 5 lines; adding
  `--min-size 0` gives 19, the same as no config at all. `config init` into a
  clean directory then scanning produces output byte-identical to scanning with
  no config — which was the point of both template fixes.
- Mutation testing and branch coverage: not re-run this session

## For Next Task

**Task 4 (`clean` with no path) has its inputs ready.** `Rules::roots()` yields
only the rules that both compiled and carry a root — exactly the set to walk —
and `Rules::is_empty()` answers "this config covers nothing". A `root = "*"` rule
contributes no root, so a user with only the built-in defaults and no path will
have to be told to name one.

**Gotchas discovered:**

- **Integration tests read the real config unless stopped.** Three failed the
  moment the config was wired to behaviour, because the machine running them had
  `depth = 0` in `~/.config/disk-tools/config.toml`. `run()` now sets
  `XDG_CONFIG_HOME` to an empty temp directory; any new test that spawns the
  binary another way must do the same.
- A config written by an **earlier** `config init` still contains `n = 20` and
  `depth = 0`. Those keys are still valid and still honoured — `depth = 0` now
  meaning the root alone. Anyone who ran `config init` before this task should
  re-run it with `--force`, or delete the two lines.
- `--min-size` no longer shows `[default: 0]` in `--help`, by construction. The
  doc comment says it instead.
