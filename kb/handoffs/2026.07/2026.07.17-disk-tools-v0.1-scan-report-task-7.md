# Handoff: Task 7 — Tree renderer (dust-style bars)

[2026.07.14-disk-tools-v0.1-scan-report.md](../../specs/2026.07/2026.07.14-disk-tools-v0.1-scan-report.md)

## Completed

- `cli/src/render/mod.rs` + `cli/src/render/tree.rs`: `render_tree(&ScanTree, &RenderOptions) -> String` — a pure, width-injected renderer. DFS, children ranked by size descending; emits until the `-n` budget is spent, stops past `--depth`, hides entries below `--min-size` (and their subtree). `--apparent` switches the ranking/size unit. `format_size` (1024-based) and the bar/percent layout live here.
- **Bars are parent-relative:** each entry shows its share of its immediate parent (the parent is 100%) as a percentage and a fixed-width bar whose filled blocks are **right-aligned**. The size + name + bar + percent columns fill the terminal width, so the bar/percent block is flush against the **right edge**; over-long names are truncated with `…`.
- `cli/src/main.rs`: wires `scan` + `render_tree`; computes the width via `terminal_size` with a fixed 80-column fallback for non-tty. This is the first task that prints a report.
- `cli/Cargo.toml`: `terminal_size = "0.4"`.

## Decisions Made During Implementation

- **`format_size` in the CLI, not `core/units.rs`.** Formatting is a display concern; the core "knows nothing about terminals". The §2 diagram's `core/units.rs` is stale (no task builds it); Task 7's key files already reflect the CLI placement.
- **Bars reworked mid-task at the user's request.** The spec's original AC4 ("bar proportional to the largest sibling") was replaced with: parent-relative percentage (parent = 100%), right-aligned fill, block pinned to the terminal's right edge, `…` truncation. Spec §8.2.5 and AC4 updated to match. The percentage of a nested entry is relative to its **immediate parent**, not the root.
- **`fraction(size, parent)` treats `size == parent` as `1.0`** — so the root (which passes its own size as the reference) is always 100%, including an empty (0-byte) root, and a sole child carrying all its parent's bytes reads 100%.
- **`format_size` rolls over at the rounding boundary** — `1048575` prints `1.0M`, not `1024.0K`; the unit climbs while the one-decimal-rounded value still reaches 1024.
- **Layout constants + `GUTTER_COLS`** keep `name_columns`'s width arithmetic in one place; `{percent:>pw$}` derives its width from `PERCENT_COLS` so the two can't drift.

## Deviations from Spec

- **AC4 changed** (bar semantics) — a user-directed change during implementation, not a silent deviation; spec §8.2.5 + AC4 were updated in step.
