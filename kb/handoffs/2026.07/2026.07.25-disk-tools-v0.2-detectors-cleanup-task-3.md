## Decisions Made During Implementation

- **No clock, no environment — both are inputs.** `core/src/options.rs` already
  promises the core "consults no environment", so `user-caches` takes a
  `UserDirs` and the age rule takes its `now`. This is what makes "a cache
  outside the home does not match" testable with a fake home, and the boundary
  testable without the clock. Independently, `std::env::home_dir` is still
  deprecated at MSRV 1.85 (verified by compiling under `+1.85`) and documented as
  wrong on Windows, so reading it here was never an option.
- **`Age { older_than, now }` rather than two fields.** A reviewer found the trap:
  `DetectOptions { older_than: Some(d), ..Default::default() }` compiled, looked
  armed, and matched **nothing**, because `now` stayed at its sentinel. Pairing
  them makes that state unrepresentable instead of merely documented — and
  `DetectOptions` can now derive `Default` rather than hand-writing it.
- **`Detection`, not `Match`.** Renamed on review: `Match` reads as a search hit,
  and Task 4 introduces the richer `Candidate` right beside it. Cheap now,
  expensive once Task 4 depends on it — the same reasoning as Task 1's
  `to_trash` → `move_to_trash`.
- **`UserDirs` derives its own cache roots** rather than taking a prepared list.
  *Which* directories count as user caches is knowledge about the category, so it
  belongs beside the category; the frontend only answers "where is home".
- **Cache-root comparison is ASCII-case-insensitive on Windows only.** A home
  resolved as `C:\Users\Me\AppData\Local` must match a scan that walked
  `c:\users\me\…`. Off Windows it stays exact: APFS can be case-sensitive and
  Linux is, so folding case there would make two genuinely different directories
  compare equal — and this comparison decides what becomes a deletion candidate.
- **A `doc` recipe in `verify`.** A public item documenting a link to a private
  one resolves to nothing and clippy does not see it. Two reached code review —
  Task 2's and this one's — so the gate now exists. Confirmed it fails on a
  deliberately broken link before being committed.

## Deviations from Spec

- **One `detect()` rather than `junk()` + `old()`.** §2's diagram sketches two
  calls, but §8.2.2 step 1 applies the age rule only to nodes "not already
  claimed by a junk rule", which couples the passes. The per-node rules remain
  separate functions internally.
- **The no-descend rule extends to age matches.** §8.2.1 step 5 states it only for
  junk. Left literal, an old directory of old files would produce a candidate for
  each, and Task 4's total — a plain sum of `allocated` — would count the same
  bytes repeatedly. Recorded in the spec.
- **A disabled category still lets the age rule claim the node.** "Not already
  claimed" is read as "claimed by an *enabled* rule". Recorded in the spec.
- Ten tests beyond the spec's list, each covering a way a rule could over-match.

## For Next Task

Task 4 — **plan: denylist, tiers, reclaimable size**. `detect()` gives it the
candidate list.

What it can rely on:

1. **No detection nests inside another**, so summing `allocated` over them counts
   no byte twice. This is load-bearing for the "reclaimable equals the sum"
   criterion.
2. **`Detection.allocated` is the whole subtree's**, already attributed — the
   hardlink twins inside it are zeroed, so the figure is what deleting the
   subtree would free, before the `shared` question.
3. **Order follows the tree**, whose children are sorted by path, so the list is
   deterministic. Task 4 still sorts, since its own criterion demands it.
4. **`Category::Old` means confirm-tier** and the four safe-list categories mean
   auto-tier — the mapping Task 4's first criteria describe. Note a disabled
   category can arrive as `Old`, so tier follows the category reported, not the
   name of the directory.

Known limitations, deliberately not fixed:

- **Cache-root matching is exact off Windows.** A path differing only in case, or
  relative where the root is absolute, is missed. This only ever *weakens* the
  safe-list — it cannot make the wrong directory a candidate — and closing it
  properly would need `canonicalize()`, which the project forbids.
- **`visit()` recurses.** Depth is bounded by tree depth, and the tree it walks
  was itself built by the recursive `tree::build_node` at the same depth: a tree
  too deep for `visit()` could not have been constructed in the first place. No
  new exposure, so no fix here.
- **`user-caches` matches nothing until the CLI supplies a home** (Task 6). That
  is the safe default, but it means the category looks inert in any manual test
  run before then.
