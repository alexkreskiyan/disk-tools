## Decisions Made During Implementation

- **`filesize` rejected** — the crate the spec named. Its Windows `file_real_size_fast` calls `std::fs::canonicalize` on every file (`filesize-0.2.0/src/lib.rs:85`), which violates the spec's own §4 constraint, adds a syscall to the hot path, and (per the research report) fails outright with OS error 1 on RAM disks, network drives and Docker mounts. It also **ignores the `metadata` argument** on Windows, so the "fast" variant isn't. On Unix it wraps a single `metadata.blocks() * 512`. Net: a dependency that earns nothing on Unix and breaks a rule on Windows.
- **`forbid` → `deny`** — forced by the above. Windows exposes no safe allocated-size API (`std::os::windows::fs::MetadataExt` has `file_size`, `volume_serial_number`, `file_index` — nothing allocated), so `GetCompressedFileSizeW` needs FFI. `forbid` **cannot** be lifted by `#[allow]` — that is the entire difference from `deny`. Re-verified that `deny` still bites: `unsafe` in a non-Windows module fails the build citing `lib.rs:16`.
- **Windows path never canonicalized** — `encode_wide` + NUL on the path as the walk produced it.
- **`INVALID_FILE_SIZE` handling** — it is also a legitimate low dword, so it only signals failure when `GetLastError()` is non-zero. `windows-sys` doesn't export the constant; declared locally as `u32::MAX`.
- **`pub(crate)` visibility** — sizing is internal; the public surface stays the model types plus (later) `scan()`.
- **`measure` takes metadata rather than fetching it** — §8.2.1's one-metadata-call-per-file rule is the tool's main performance lever.

## Deviations from Spec

1. **`filesize` not used** (spec §8.2.1 named it). Reason above. Spec §8.2.1 + Task 2 notes rewritten.
2. **`#![forbid(unsafe_code)]` → `#![deny(unsafe_code)]`** — weakens a spec Protected Element and Task 1's already-`[x]` AC #3. Both amended in place rather than left to rot silently. Any *further* `allow` should get the scrutiny this one got.
3. **`#[allow(dead_code)]` on `mod size;`** — temporary. Nothing calls `measure` until Task 3's walk; **remove the allow then**.
