## Feature Spec

[v0.3 — configuration and declarative rules](../../specs/2026.07/2026.07.26-disk-tools-v0.3-config-rules.md)

## Completed

- `core/src/rules.rs` — `Rule`, compiled `Rules`, `RuleError`, `Tier`, `UserDirs`,
  `builtin_rules()`, `age_rule()`. One `GlobSet` across all rules with a
  pattern-index-to-rule-index map; **lowest rule index wins**, which is how "list
  order is precedence" is implemented rather than asserted.
- `core/src/detect.rs` — rewritten. One DFS, one `globset::Candidate` per node,
  root pruning at directory level. `Category`, `CategorySet`, `Age` and
  `UserDirs::cache_roots` deleted.
- `core/src/clean.rs` — `Candidate.rule: String` replaces `Candidate.category`;
  tier, `min_size` and `requires_clean_repo` come from the rule.
  **`CONFIRM_ONLY_NAMES` deleted.**
- CLI — `args.rs` builds `Rules::builtin` plus the age rule; the report prints
  rule names in a column sized from the data.
- The denylist is untouched: `DENIED_ROOTS`, `denylist()` and `is_denied`'s dual
  raw/normalised check are byte-identical to v0.2.

## Decisions Made During Implementation

- **`Rule.root` is `Option<String>` in the core**, `None` meaning "wherever the
  scan goes". The plan's stated resolution of the spec's D4: applying "root is
  mandatory" to the built-ins would root all five at `~`, and
  `CleanOptions::default()` has no home, so every rule would drop and ~25
  `clean.rs` tests would stop matching anything. The config schema still requires
  `root` (Task 2 validates it).
- **`user-caches` split into `user-caches` + `windows-temp`.** v0.2 folded
  `~/.cache`, `~/Library/Caches` and `%LOCALAPPDATA%\Temp` into one category; the
  third has a different root, and one rule cannot have two. This makes the
  different anchoring visible instead of hidden in `cache_roots()`.
- **`UserDirs` moved to `rules.rs`** — the rules are what resolve roots now.
  **`Tier` moved there too**, since `Rule` carries it; `clean.rs` re-exports it so
  the public API is unchanged.
- **`same_path` deleted.** Its last caller was `cache_roots()` matching. Its
  separator/dot-noise property is now asserted through `is_within`, which shares
  the same component-wise comparison.
- **`Mode::Clean.clean` is boxed.** `Rules` carries two glob automata, and clippy
  correctly objected that every `Mode::Scan` would otherwise pay for the space.
- **No `let` chains.** They stabilised in 1.88 and the MSRV is 1.85 — caught by
  `cargo +1.85 check`, not by `just verify`.

## Deviations from Spec

- **`Rule.root` optional in the core** (D4). Recorded above and in the approved
  plan; the config schema is unchanged.
- **`**/*.pyc` now also matches a directory named `*.pyc`.** v0.2 checked the
  extension only after `if node.is_dir { return None }`, so a directory ending in
  `.pyc` was skipped. Gitignore semantics — which the trailing-slash convention
  commits to — match both. A tiny widening in the deletion direction; expressing
  "file only" would need syntax the config does not have. Flagged rather than
  silently taken.
- **One incidental fix outside the task.** The `--safe` line printed "1 more
  candidate **need** confirmation; --safe is hiding **them**", and
  `counts_are_singular_where_they_should_be` asserted the broken string. The verb
  and pronoun now agree with the noun. Found by running the binary, which is also
  how the v0.2 `Intent` bug was found.

## For Next Task

**Task 2 (config file) can use what is already exported.** `builtin_rules()` is
public precisely so `config init` renders *that* list rather than a second copy
that could drift. The spec's AC — "the file it wrote parses back to an identical
rule list" — is the guard.

**`Rules::roots()` already exists** for Task 4's `clean` with no path. It yields
only the rules that both survived compilation and carry a root, which is exactly
the set to walk. `Rules::is_empty()` answers "this config covers nothing".

**Gotchas discovered:**

- `globset` patterns use `/`; a Windows root's `\` is translated in
  `glob_prefix`. `Candidate` normalises the path being tested the same way, so
  both sides agree — but a pattern built by hand elsewhere would not.
- A trailing `/` cannot be given to `globset` at all. It is stripped and recorded
  in `include_dir_only`; any new pattern source must do the same.
- `RuleError` carries the pattern **as the user wrote it**, trailing slash
  included. Task 2's error messages should quote that, not the stripped form.
- `DetectOptions::default()` is the built-ins with no home — deliberately, so
  `CleanOptions::default()` still behaves like a first v0.2 run. Task 3's
  precedence work should not quietly turn that into "no rules".
- The upper-bound benchmark pass now uses an age rule with an impossible
  threshold (`now = UNIX_EPOCH`, so `checked_sub` underflows). If that ever starts
  claiming, `detect*` silently stops measuring the full traversal — the pass
  asserts `full.is_empty()` to catch it.
