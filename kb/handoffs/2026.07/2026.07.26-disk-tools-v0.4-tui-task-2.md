## Decisions Made During Implementation

- **`core::allocated_size` is public now.** `metadata.len()` is the *apparent*
  size; `scan` reports allocated. Left alone, the same file would have read
  differently in two verbs — and worse from Task 3, where directory totals are
  allocated and would sit in the same column as apparent file sizes. T3 ("the TUI
  lists itself") was about `ScanNode` and the `--json` shape, not about
  reinventing `blocks * 512` with a different answer.
- **`..` is an ordinary row**, so `Enter` on it needs no case of its own and the
  parent is visibly there to be entered.
- **Leaving lands the cursor on the directory just left.** What a user was inside
  is what they will look for.
- **`ratatui::backend::TestBackend`** — this is the answer to "CI has no
  terminal", and it is better than what Task 1 settled for. Layout is now
  asserted: the header's order marker, the directory suffix, a size formatted as
  `scan` formats it, the key line, and that narrow or short terminals do not
  panic. A `#[ignore]`d `show` test prints the screen, following `phase_split`'s
  precedent in the core.

## Three things the tests caught

- **`reverse` reversed too much.** The doc said "unknown sorts last in both
  directions"; the code reversed the whole comparison, so unknowns floated to the
  top. `reverse` now applies only *between two known values* — the obvious
  one-line way to write this is the wrong one.
- **`open` put the cursor somewhere arbitrary.** It reused the "hold onto the
  entry" logic, so the cursor followed whatever `read_dir` happened to return
  first to wherever the sort put it. Opening starts at the top; only a change of
  order preserves.
- **A test spun forever.** `while cursor_name(&app) != "x" { app.move_down() }`
  never terminates when `x` is absent, because `move_down` stops at the last row.
  It hung a run for over a minute. Replaced by `point_at`, which finds the index
  and asserts it exists.

## For Next Task

**Task 3 is lazy directory sizing.** `Entry.size` is already `Option<u64>` and
`None` for directories, the column already renders empty for them, and the sort
already puts unmeasured directories in name order. What is missing is
`core::measure` and the thread that drives it.

**Gotchas discovered:**

- **`script -q /dev/null` reports a terminal size of 0×0**, so nothing renders
  and layout cannot be seen that way. Use `TestBackend`; the `show` diagnostic
  prints a screen at any size.
- Clippy's `cmp_owned` fires on `entry.name == OsString::from("..")` — compare
  against the `&str` directly.
- `App::go` is the single place that changes directory. Task 3's "restart the
  measurement" will want to cancel from there.
