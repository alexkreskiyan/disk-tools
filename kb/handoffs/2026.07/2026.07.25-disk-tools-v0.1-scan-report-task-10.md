## Decisions Made During Implementation

- **CI caught a real cross-platform bug on its first run.** `windows-latest` failed
  `allocated_is_block_multiple`: `GetCompressedFileSizeW` returned exactly `10` for
  a 10-byte file. NTFS stores a file that small **resident inside its MFT record**,
  where it owns no cluster of its own — so `10` is the honest answer and the
  *assertion* was wrong, not the code. The 512-multiple invariant is now
  `#[cfg(unix)]`; Windows asserts "whole 512-byte units **or** exactly the logical
  length", which still catches a garbage FFI reading. The behaviour is documented
  in the README's sizing section. Note this contradicts the cross-platform wording
  of **Task 2's third AC** ("allocated is a whole number of filesystem blocks") —
  that AC holds on Unix only.
- **`extractions/setup-just@v4`**, not the `@v3` the plan sketched — v4 is current.
- **No MSRV job.** `rust-version = "1.85"` is pinned in the manifest and `@stable`
  satisfies it; a dedicated 1.85 job is not an AC. Consequence recorded below.
- **`.gitattributes` added preventively.** CI is green on Windows without it, but a
  CRLF checkout under Git for Windows' default `core.autocrlf=true` would make
  `cargo fmt --check` report a diff on every file — a trap for the first Windows
  contributor.
- **README examples are captured from real runs** against a scratch fixture tree,
  including the skipped-entries summary (`chmod 000`) and `--json | jq`. Nothing in
  the README is hand-written output.
- **`--apparent` is classified display-only.** `ScanOptions.apparent` is never read
  by the core — both sizes are always measured; the flag only switches the ranking
  and display unit in `cli/src/render/tree.rs`.
- **CLAUDE.md's Key Concepts section was filled in** (it still said "no abstractions
  defined yet"). Slightly beyond the AC's key files, but required by CLAUDE.md's own
  standing rule that code changes be reflected in documentation.

## Deviations from Spec

- The spec's §2 sketch lists `core/src/units.rs`; it was never split out — size
  formatting lives in `cli/src/render/tree.rs`, since only the renderer needs it.
  CLAUDE.md now records this rather than implying a missing module.
- The spec describes the walker as `read_dir + rayon::scope`; the implementation
  fans out with `into_par_iter` (`core/src/walk.rs:168`). Same design, different
  rayon API. CLAUDE.md corrected; the spec's §2 prose still says `scope`.

- **Remaining findings (3, not fixed):**
  1. `core/src/size.rs` — **no Windows test can fail** if `allocated()` regressed to
     returning `metadata.len()`: `sparse_file_allocated_less_than_apparent` is
     `#[cfg(unix)]`, and the new Windows arm accepts `allocated == apparent`.
     Closing it needs an NTFS sparse fixture (`FSCTL_SET_SPARSE`) or a compressed
     file — more FFI in a crate that denies `unsafe` outside one function.
  2. `.github/workflows/ci.yml` — only `stable` is installed, so code using an API
     stabilized after 1.85 would pass CI while breaking the declared MSRV.
  3. `cli/src/main.rs:49,56` — `disk-tools <path> | head` **panics**:
     `failed printing to stdout: Broken pipe (os error 32)`. Found while capturing
     README examples; unrelated to this task, but user-visible.
